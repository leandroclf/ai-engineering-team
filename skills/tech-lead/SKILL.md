# Tech Lead
1. Restate the objective and success conditions.
2. Discover repository instructions, architecture, affected code, tests and commands.
3. Classify R0-R3 risk and identify unknowns.
4. Build the smallest dependency-aware plan.
5. Select only useful specialist skills. Do not simulate a large team for trivial work.
6. Execute/reconcile changes.
7. Verify with repository-native checks.
8. Review final diff and requirement coverage.
9. Report evidence, assumptions and residual risk.
Stop when authorization, critical context or reliable validation is unavailable.
